# Отчёт независимой проверки

Проверено на macOS, Python 3.9.6, 29 октября 2026 года, после добавления автоматического статуса «Утерян», ручного удаления со склада и миграции базы. Команды:

```text
python3 -m unittest discover -s tests -q
python3 -m compileall -q cartridge_app tests
```

Итоговый результат после реализации автоматической утраты: **59 тестов, 51 успешно, 8 пропущены**; компиляция всех модулей и тестов прошла. Шесть пропусков связаны с отсутствием Pillow, два — с отсутствием рабочего графического сеанса Tk. Windows-сборка и визуальная проверка не выполнялись. Реальные временные SQLite-файлы создавались заново для каждого сценария; пользовательская база не использовалась.

Обработчики и адаптивная геометрия проверены без реального окна; это не визуальная проверка интерфейса. Для пакетных операций проверено, что ID добавляется в очередь без записи, а подтверждение вызывает атомарный сервис. Окно системного Tk в этой среде завершается с кодом 134, поэтому скриншоты «до/после» и визуальное сравнение не выполнены. В Parallels нужно проверить контраст, фокус с клавиатуры, модальные окна и компоновку при 100/125/150% масштабе. Тест `RealTkSmokeTests` включается `RUN_GUI_TESTS=1` в рабочем графическом сеансе Windows.

XLSX проверен как ZIP/OOXML, включая экранирование текста и явный текстовый тип ID. Открытие в Microsoft Excel здесь не выполнялось. В рамках этой проверки Windows EXE не собирался: текущая среда macOS, рабочего Windows-сеанса для сборки/проверки нет. Запуск PowerShell/PyInstaller и новой панели в готовой Windows-сборке не проверен.

## Обязательная приёмка готовой Windows-сборки

1. Распаковать всю папку на разрешённом компьютере без Python и отключить сеть; проверить запуск без администратора.
2. На разрешениях 900×600 и типичном рабочем разрешении, при масштабе 100%/125%/150%, проверить читаемость и доступность кнопок, прокрутку склада/журнала и все формы.
3. Сохранить профиль, добавить `0001` и `0002` одной модели, изменить только первый, проверить поиск/сортировку/фильтр.
4. Отправить и вернуть `0001`; проверить ошибки неизвестного ID, неправильной даты и недопустимого перехода.
5. Просканировать партию списания, проверить список, одним нажатием подтвердить операцию и проверить журнал.
6. Закрыть/открыть EXE: проверить ID, профиль и историю; открыть экспорт XLSX согласованным просмотрщиком и проверить `0001`.
7. Сделать копию, внести изменение, восстановить; убедиться в наличии страховочной копии и возможности её восстановления.
8. Получить подтверждение ИТ на запуск конкретной сборки. Если запуск блокируется, не обходить политики.

## Дополнение: настройки оформления, 29 октября 2026

После интеграции панели настроек независимо выполнены:

```text
python3 -m unittest discover -s tests -q
python3 -m compileall -q cartridge_app tests
```

Результат полного набора: **51 тест, 43 успешно, 8 пропущены**. Компиляция всех модулей и тестов прошла. В новом `tests/test_settings_preferences.py` — 22 теста: 15 успешно, 7 пропущены.

Фактически проверены сохранение настроек и чтение новым экземпляром хранилища; восстановление значений по умолчанию при повреждённом JSON/неподдерживаемой версии; валидация темы, языка, шрифта, размеров, цветов и границ подложки; откат файла и состояния в памяти при ошибке атомарной записи; сброс настроек без изменения соседних файлов склада и резервных копий. Проверены известные значения контраста 1:1 и 21:1, предупреждение о слабом контрасте и рекомендуемые цвета. По умолчанию тема хранится как `system`: тест подтверждает обращение к системной теме только для этого режима; явные `light`/`dark` обходят системный выбор.

Для изображений без декодера проверены понятная ошибка отсутствия Pillow, запрет удаления файла вне каталога изображений, сброс только принадлежащих приложению файлов фона. Обработчики панели проверены без окна: отказ от сброса не вызывает сохранение/удаление, отмена нового изображения удаляет только ожидающий файл, неудачное сохранение не перестраивает панель.

**Пропуски:** Pillow не установлен в доступном Python, поэтому 6 тестов настоящего декодирования JPEG/PNG/WebP, повреждённых файлов, лимитов, уменьшения и ошибки сохранения изображения пропущены. Ещё 2 теста требуют рабочего графического сеанса Tk и включаются `RUN_GUI_TESTS=1`: общий экранный тест и открытие панели с переключением темы, сохранением и закрытием. Они не выполнялись в текущем доступном сеансе без рабочего графического дисплея (`DISPLAY` не задан; системный macOS Tk не открывает окно). Читаемость, расположение, смена темы/языка в настоящем окне и изображения **не считаются визуально проверенными**.

При просмотре интеграции обнаружены и переданы разработчикам проблемы импорта даты, смешения менеджеров размещения, понижения Canvas и потери предпросмотра ожидающего изображения. Исправления проверены чтением обновлённого кода; настоящая графическая проверка остаётся в Windows-приёмке. После установки зависимостей на разрешённой машине сборки повторите полный набор: тесты декодирования должны выполняться без пропуска. Затем включите `RUN_GUI_TESTS=1` и проверьте панель вручную при разных масштабах, отказах записи и недоступном сохранённом фоне.

Регрессионно воспроизведено удаление нового фона после успешной записи настроек при ошибке очистки старого файла. После исправления проверены оба случая: отсутствующий старый файл и искусственная ошибка отрисовки после успешного сохранения. Тест использует реальные `ImageStore` и `PreferencesStore`: новый файл остаётся, повторное чтение `preferences.json` ссылается на него. Содержимое изображения в этом тесте заменено байтовым образцом: это проверка сохранности файлов, не декодирования. Финальный повторный прогон после исправления: **51 тест, 43 успешно, 8 пропущены**; `compileall` успешно. Windows-сборка в рамках этой проверки не выполнялась.

## Дополнение: удаление со склада

Удаление проверено на временной SQLite-базе: экземпляр исчезает из активного списка, действие записывается в историю со снимком профиля и данными экземпляра. Повторное использование ID запрещено. Искусственный сбой записи истории откатывает и отметку удаления; проверено сохранение состояния после перезапуска. Отдельно проверены миграция существующей базы и восстановление резервной копии версии 1 без потери записей. Подтверждение отменяет удаление без вызова сервиса. Итоговый полный набор на этом этапе: **56 тестов, 48 успешно, 8 пропущены**.


## Дополнение: автоматический статус «Утерян»

Порог вычисляется как 7×24 часа от `recorded_at` фактической записи отправления (не от введённой даты операции). Сервисная проверка переводит все просроченные активные экземпляры `На заправке` в `Утерян` и добавляет событие истории внутри одной транзакции. Повторная проверка идемпотентна. UI выполняет проверку при запуске и затем раз в минуту; при закрытом приложении просроченные экземпляры обрабатываются при следующем запуске. В журнале хранится причина автоматического перехода/дедлайн.

Проверены момент до порога, ровно 7 дней и после порога, единственность события при повторном опросе и откат статуса при искусственном сбое записи истории. Полный прогон: **59 тестов, 51 успешно, 8 пропущены**; `compileall` успешно. GUI-проверка и Windows EXE в этой среде не выполнялись.

Контрольная SHA-256: `a1a2d8963049c60c02dba731ae374cbd4a84bde1a13edcdd90d21de3a93d97bd`. Файл новее текущих исходных файлов.
