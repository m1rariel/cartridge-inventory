# Учёт картриджей — версия 1.0

Автономное приложение для одного пользователя на одном компьютере. Русский и английский интерфейсы, настройки темы и оформления, SQLite, журнал операций, профиль, экспорт XLSX и резервные копии. Сеть, сервер, регистрация и Microsoft Excel для работы не нужны.

**Состояние поставки:** доступны исходники и сценарий сборки Windows one-file EXE. Партии отправления, прибытия и списания принимают ID как клавиатурный ввод и ждут Enter после каждого кода; отдельная интеграция со сканером не добавлялась. Проверки имеющегося Windows ARM64 EXE и их ограничения описаны в [отчёте](docs/TEST_REPORT.md).

## Запуск на рабочем компьютере без установки

После сборки на отдельном разрешённом компьютере получите `CartridgeAccounting-Windows.zip` или используйте файл `dist-onefile\CartridgeAccounting.exe`:

1. Убедитесь, что организация разрешает запуск этого переносимого приложения. Запрет установки не означает разрешения запускать EXE. Если запуск запрещён политиками, согласуйте приложение с ИТ; обход ограничений не предусмотрен.
2. Если используете ZIP, распакуйте его содержимое. В one-file EXE все компоненты программы собраны в одном файле.
3. Запустите `CartridgeAccounting.exe`. Права администратора, установленный Python, Node.js, Excel и сервер БД не нужны. Интернет во время работы не используется.
4. Откройте «★ Профиль», введите организацию и ФИО, сохраните. Пустой профиль допустим, но тогда новые записи журнала будут без этих сведений.
5. В «Склад» нажмите «+ Добавить», введите текстовый ID и наименование. Например, `0001` и `0002` одной модели — два разных экземпляра.

EXE можно обновлять независимо от данных. Перед обновлением сделайте резервную копию. Закройте программу, замените старый EXE новым и запустите его. **Не удаляйте пользовательский каталог данных.** Демонстрационные записи при запуске не создаются.

## Работа

- Главное меню: «Склад», «Отправление», «Прибытие», «Списание», «★ Профиль».
- «⚙ Настройки»: светлая/тёмная тема (до ручного выбора следует системной), шрифт и размер 9–24 pt, акцентный цвет, отдельный цвет текста для каждой темы, русский/английский язык и локальный фон JPEG/PNG/WebP. Настройки сохраняются отдельно от базы учёта; «Сбросить настройки» не удаляет склад, профиль и журнал. Изображение до 10 МБ, не более 6000 × 6000 пикселей и 24 Мп.
- Склад: поиск по ID/наименованию без учёта регистра, фильтр статуса, сортировка нажатием заголовка. Кнопка «Редактировать» или двойной щелчок открывает небольшую форму; отдельной страницы карточки нет. ID неизменяем.
- Удаление экземпляра: выделите строку и нажмите «Удалить со склада». После подтверждения запись исчезнет из активного склада; журнал сохранится, ID останется занятым.
- Интерфейс открывается развёрнутым на Windows и подстраивает минимальный размер под экран. В таблицах остаётся горизонтальная прокрутка, панель поиска компактнее на узком окне, диалог редактирования учитывает доступный размер экрана.
- Наименование описывает модель, но не служит ключом. Правка наименования/принтеров относится только к выбранному физическому экземпляру; другие записи той же модели не меняются.
- «Отправление»: сканируйте ID экземпляров со статусом `Готов`; каждый попадает в список ожидания по Enter. Одна кнопка «Отправить партию на заправку» переводит всю партию `Готов → На заправке` в одной транзакции. «Прибытие» работает аналогично для возврата из заправки: одна кнопка «Принять партию в склад» переводит всю партию `На заправке → Готов`. Неизвестный ID, повтор, неподходящий статус и неверная дата показываются на экране без модального окна. Ошибка при сохранении любого экземпляра откатывает всю партию.
- «Списание»: сканируйте ID экземпляров со статусами `Готов` или `На заправке`; список проверяется без записи в базу. Кнопка «Списать партию» подтверждает всю партию одним действием и переводит её в `Списан` одной транзакцией. Пустой список не отправляется; ошибка при любом ID откатывает всю партию. Списанный экземпляр нельзя редактировать или переводить в другой статус.
- В партиях отправления, прибытия и списания ID проверяются сразу при сканировании. Одна кнопка в конце подтверждает весь список. Дата задаётся как `ГГГГ-ММ-ДД`, по умолчанию сегодня. Дата раньше предыдущей операции запрещена.
- Если картридж остаётся «На заправке» 7×24 часа с момента фактической записи отправления, приложение автоматически меняет статус на «Утерян» и записывает событие в журнал. Пока приложение запущено, проверка выполняется раз в минуту; если срок истёк, пока программа была закрыта, статус обновится при следующем запуске. Изменение статуса и журнал сохраняются одной транзакцией.
- «Дата» склада — дата последней операции, включая редактирование; у нового экземпляра — дата создания. Редактирование датируется сегодняшним днём, либо последней датой экземпляра, если она находится в будущем. Будущие даты явно не запрещены требованиями и разрешены.
- Журнал доступен со склада и из профиля. Выберите запись для полных сведений. Он хранит дату операции отдельно от фактического времени записи с часовым поясом, старый/новый статус, изменения полей и снимок профиля. Изменение профиля не переписывает прошлое.
- «Экспорт списка в XLSX» выгружает текущий отфильтрованный и отсортированный список. В первых строках перед таблицей печатаются организация и ФИО из сохранённого профиля. ID записывается текстом с ведущими нулями; формулы не создаются. XLSX — отчёт, а не резервная копия.

## Визуальная система

Светлая и тёмная темы используют общие дизайн-переменные. Цвета, шрифты и базовый размер текста меняются сразу. Навигационные заголовки и обратная связь плавно меняют тон за 120 мс; анимация отключается при системном запрете анимаций Windows. Видимый фокус и состояния hover/pressed/disabled заданы стилями ttk. Геометрия окна, диалогов и перенос длинных подписей настраиваются `adaptivity.py`.

Tkinter не умеет размывать фон под дочерними элементами и задавать им альфа-прозрачность или скруглённые границы. Поэтому панели используют непрозрачный высококонтрастный fallback со светлой рамкой; системное Liquid Glass в этом Windows-приложении не имитируется низкоконтрастным текстом поверх прозрачного окна. Пользовательское фото хранится локально и рисуется отдельным слоем позади главного окна; из-за непрозрачности дочерних окон Tk оно видно в безопасной внешней рамке и доступно для предпросмотра в настройках, но не просвечивает сквозь формы и таблицы.

## Где находятся данные

Windows: `%LOCALAPPDATA%\CartridgeAccounting\inventory.sqlite3`, обычно `C:\Users\<пользователь>\AppData\Local\CartridgeAccounting\inventory.sqlite3`.

Файл настроек: `%LOCALAPPDATA%\CartridgeAccounting\preferences.json`; пользовательские фоновые изображения — в подкаталоге `settings_assets`. Настройки и фон хранятся локально, отдельно от SQLite и без сети. SQLite-файл резервируется средствами приложения; для переноса предпочтений отдельно сохраните `preferences.json` и `settings_assets` при закрытом приложении.

Путь показан в «★ Профиль». Данные сохраняются после каждой успешной операции. Изменение экземпляра и запись журнала выполняются одной SQLite-транзакцией. Ошибка записи откатывает обе части.

Для разработки на macOS: `~/Library/Application Support/CartridgeAccounting/inventory.sqlite3`. На Linux: `$XDG_DATA_HOME/CartridgeAccounting/inventory.sqlite3`, либо `~/.local/share/CartridgeAccounting/inventory.sqlite3`.

## Резервные копии и восстановление

1. В «★ Профиль» нажмите «Создать резервную копию» и выберите файл `.sqlite3`. Рекомендуется отдельный разрешённый носитель или каталог резервирования, а не только тот же диск. Копия включает склад, профиль и весь журнал.
2. Делайте копию в конце рабочего дня, перед обновлением и важными изменениями. Автоматического ежедневного расписания в первой версии нет.
3. Для восстановления нажмите «Восстановить из копии», выберите файл и подтвердите замену. Будут восстановлены **все** данные из копии; более новые изменения исчезнут из текущей базы.
4. Перед заменой приложение проверяет файл и автоматически сохраняет текущую базу в `backups\before-restore-<дата-время>-<суффикс>.sqlite3` рядом с рабочей базой. Путь покажет сообщение. Эту страховочную копию можно восстановить тем же способом.
5. Повреждённый или чужой файл отклоняется. Нельзя сохранять резервную копию поверх рабочей базы. Обычное копирование открытой БД вручную не используйте.

Если программа не запускается из-за повреждения рабочей базы: полностью закройте все экземпляры программы; сохраните весь каталог данных в отдельном месте для диагностики; переименуйте каталог `CartridgeAccounting`, не удаляя его. Запустите приложение с новым пустым каталогом и восстановите известную исправную копию через профиль. Если ошибка связана с доступом, обратитесь к ИТ, не меняйте корпоративные политики. До восстановления не начинайте новый учёт.

## Сборка на отдельном компьютере разработчика

Собирайте в Windows той архитектуры, для которой нужен результат, с Python 3.12 и стандартным Tkinter на **сборочном** компьютере. Это не требование к рабочему компьютеру пользователя. Версии PyInstaller и Pillow закреплены в `requirements-build.txt`; Pillow и зависимости включаются в один переносимый EXE. Зависимости сборки загружаются только на машине сборщика; целевой компьютер не требует Python, Pillow или Excel. Архитектура результата соответствует Python сборщика.

В PowerShell из каталога проекта:

```powershell
.\build-windows.ps1
```

Сценарий создаёт `.venv-build`, устанавливает PyInstaller, запускает тесты, собирает `dist-onefile\CartridgeAccounting.exe` и архив `dist\CartridgeAccounting-Windows.zip` с EXE и инструкцией. Не меняйте политику запуска PowerShell в обход правил организации. Если сценарии не разрешены, на разрешённой машине сборки выполните те же команды вручную:

```powershell
py -3.12 -m venv .venv-build
.\.venv-build\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv-build\Scripts\python.exe -m unittest discover -s tests -v
.\.venv-build\Scripts\python.exe -m PyInstaller --noconfirm --clean --windowed --onefile --collect-all PIL --name CartridgeAccounting --distpath dist-onefile --workpath build-onefile run.py
```

Перед передачей пользователю проверьте готовый EXE на согласованной Windows без Python и без сети по [чек-листу](docs/TEST_REPORT.md). Подпись EXE и корпоративное разрешение запуска ещё не получены.

## Быстрая проверка изменений в Parallels

Если папка `C:\Mac\Home\Desktop\cartridge-accounting` открывает общую папку Mac, редактируйте исходники на Mac в этой же папке. В Windows VM откройте PowerShell в каталоге проекта и запустите наблюдатель:

```powershell
.\.venv-build\Scripts\python.exe dev_watch.py
```

Наблюдатель запускает приложение прямо из исходников и следит за Python-файлами. После сохранения `.py` на Mac он перезапускает окно в VM примерно через секунду. Окно и несохранённые поля сбросятся; уже подтверждённые операции останутся в базе Windows. Не закрывайте окно PowerShell наблюдателя, пока проверяете изменения. `Ctrl+C` останавливает наблюдатель и приложение.

Для этого цикла EXE пересобирать не нужно. Когда изменения готовы, остановите наблюдатель и соберите новый EXE обычной командой PyInstaller. Запуск приложения напрямую из исходников годится для разработки, итоговую переносимую сборку всё равно проверяйте отдельно.

Запуск исходников в среде разработки с Python 3.9+ и рабочим Tk:

```text
python -m cartridge_app
python -m unittest discover -s tests -v
```

Для реального автоматического теста экранов на Windows в рабочем графическом сеансе:

```powershell
$env:RUN_GUI_TESTS = '1'
.\.venv-build\Scripts\python.exe -m unittest discover -s tests -v
```

## Допущения и отложенные вопросы

SQLite — единственное основное хранилище, XLSX — формат обмена. Слой `storage.py` изолирован от UI и правил `service.py`, поэтому его можно заменить. Новый экземпляр получает статус «Готов». Пробелы по краям ID/полей удаляются; регистр ID значим. Одинаковое наименование допускается у любого числа ID.

«Утерян» предусмотрен моделью и фильтром; команд утраты и восстановления нет. Сердце/избранное не реализовано и не показано. Импорт оставлен до получения реального файла и согласования дубликатов/обновления; структура будущего шаблона — [docs/IMPORT_TEMPLATE.md](docs/IMPORT_TEMPLATE.md). Общий справочник моделей, массовые операции, печать, сеть и роли не входят в первую версию.

Заполненное приложенное ТЗ и эскизы в доступном контексте не получены. Реализация следует подробным требованиям сообщения заказчика; совпадение с недоступными изображениями не проверено. Размеры экрана, масштабирование, целевую версию Windows и корпоративное разрешение запуска следует подтвердить при приёмке.
